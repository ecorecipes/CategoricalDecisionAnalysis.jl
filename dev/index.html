CategoricalDecisionAnalysis.jl

The applied-category-theory layer over DecisionAnalysis.jl. It re-exports every name of that package and gives the same numbers; what it adds is the structure of a decision analysis, made explicit enough to compose, to check and to prove things about.

A reader who does not know category theory can start with the first tutorial, which builds a decision analysis as a diagram of five kinds of box and reads the usual answers off it.

CategoricalDecisionAnalysis — Module
CategoricalDecisionAnalysis

The applied-category-theory layer over DecisionAnalysis.jl: the structure of a decision analysis made explicit enough to compose and to check. It re-exports every name of DecisionAnalysis and gives the same numbers; what it adds is structure.

  • Uncertainty monads and their algebras (src/monads.jl): no uncertainty, finite distributions, non-empty sets of possibilities and credal sets (IdentityMonad, DistributionMonad, PowersetMonad, CredalMonad), the structure maps that summarise an uncertain number (StructureMap: expectation, worst case, lower expectation, ...), which of them are Eilenberg-Moore algebras (is_algebra), and the monad morphisms between the monads (monad_morphism).
  • Effects and value pullback (src/effects.jl): value_pullback, implemented once for every monad and algebra, and the interchange_gap whose instances are the values of information.
  • Conditionals (src/conditionals.jl): bayesian_inverse, through sub-stochastic kernels and normalisation, so that evidence of probability zero is a value and not an exception.
  • Selection functions (src/selection.jl): SelectionFunction, selection_product, every rule of DecisionAnalysis as a selection function (rule_selection), and finite sequential problems solved by backward_induction, which refuses criteria that do not admit it, and by policy_search.
  • Information preorders (src/information.jl): experiments under garbling and partitions under refinement (is_garbling, refines), value as a monotone map (information_value), and the regret transform under coarsening (regret_coarsening).
  • Decision pipelines (src/pipelines.jl): DecisionPipeline, typed diagrams of Belief, Channel, Policy, Consequence and Utility boxes whose shape is an ACSet, composed with Catlab's compose and otimes, and their interpreters into DecisionAnalysis (evaluate, decision_problem, value_of_information, box_provenance).
  • Compositional fidelity (src/fidelity.jl): kernel_distance and the decision-loss bound read off a diagram, fidelity_bound.
  • Diagrams compiled to programmes (src/compile.jl): policy_program (a linear programme for one decision) and strategy_program (a mixed-integer programme for several), as JuMP models, with budget and chance constraints.
  • A structural value-of-information test (src/structural.jl): observation_can_matter, from the graph alone.
  • Certificates (src/certificates.jl): export_policy_certificate and export_fidelity_chain_certificate, JSON documents that the Lean checker in proofs/ decides.
  • Kernel bridges (src/bridges.jl): finite_kernel.

What the package does not claim: optimisation does not compose in general (only evaluation does, and compiled programmes); credal kernels compose in sequence only and have no string diagrams here; and the constructions are known ones, cited where they are documented.

Conventions

  • Everything of DecisionAnalysis holds: payoffs are utilities (higher is better), a payoff table is Q[a, θ] (rows = actions), a likelihood is L[z, θ] (rows = signals, columns sum to one), total variation is half the ℓ¹ distance.
  • A kernel is column-stochastic, K[y, x] = P(y | x), output first, as in FiniteKernels. The table of a pipeline box has the output axis first and then one axis per input wire.
  • Composition is in diagrammatic order: compose(p, q) and kleisli_compose(f, g) are "first p, then q".
  • Exact in, exact out: integer and rational inputs give rational results.
  • Ties are never broken at random: a selection function returns the first best point, or all of them.
  • Utilities in the examples are counts of individuals of the focal species, every example has a no-intervention action as its baseline, and every number is illustrative.

Installation

The ecosystem packages are not registered. Clone this package beside DecisionAnalysis.jl and FiniteKernels.jl, which it finds through [sources] paths; the other ecosystem packages are fetched from GitHub.

git clone https://github.com/ecorecipes/FiniteKernels.jl
git clone https://github.com/ecorecipes/DecisionAnalysis.jl
git clone https://github.com/ecorecipes/CategoricalDecisionAnalysis.jl
cd CategoricalDecisionAnalysis.jl
julia --project -e 'using Pkg; Pkg.instantiate(); Pkg.test()'
