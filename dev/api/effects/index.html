CategoricalDecisionAnalysis.default_algebra — Method
default_algebra(monad) -> StructureMap

The structure map used when none is given: IdentityAlgebra for the IdentityMonad, ExpectationAlgebra for the DistributionMonad, InfimumAlgebra (the worst case) for the PowersetMonad, LowerExpectationAlgebra for the CredalMonad and TotalRewardAlgebra for the RewardMonad.

CategoricalDecisionAnalysis.expectation_rewrite — Method
expectation_rewrite(kind::Symbol) -> Symbol

The relation that holds when a map h on the reals is moved through an expectation box, h(E X) against E h(X), by the kind of h: :affine gives :(==) (affine maps are exactly the maps that commute with expectation, Lean commutesWithMix_iff_affine), :convex gives :(<=) (h(E X) ≤ E h(X): a convex map is an oplax morphism of expectation algebras, isOplax_iff_convexOn) and :concave gives :(>=). Any other kind throws ArgumentError: a rewrite of a pipeline through an expectation is licensed only with one of these three labels. The maximum over actions is convex, which is the nonnegative interchange_gap; a risk-averse (concave) utility gives a certainty equivalent below the mean.

CategoricalDecisionAnalysis.interchange_gap — Method
interchange_gap(weights::AbstractVector, objectives::AbstractMatrix)

The interchange gap of the maximum and a weighted sum, in the form of the Lean development (interchangeGap): with objectives[i, a] the objective of action a (column) at index i (row),

Σ_i w_i max_a W[i, a]  −  max_a Σ_i w_i W[i, a],

"maximise then average, minus average then maximise". It is nonnegative for nonnegative weights (interchangeGap_nonneg). The weights need not sum to one, which is what lets one function give all three values of information:

evpi  == interchange_gap(p, transpose(Q))                       (i = state)
evsi  == interchange_gap(ones(n_signals), J),  J[z, a] = Σ_θ p(θ) L[z, θ] Q[a, θ]
evppi == interchange_gap(ones(n_cells), C),    C[c, a] = Σ_{θ ∈ c} p(θ) Q[a, θ]

(evpi_eq_interchangeGap, evsi_eq_interchangeGap, evppi_eq_interchangeGap; each is a test). Note the layout: rows are the index that is averaged over and columns are actions, the transpose of a payoff table.

CategoricalDecisionAnalysis.interchange_gap — Method
interchange_gap(α::StructureMap, m, Q::AbstractMatrix; states=axes(Q, 2), h=maximum)
interchange_gap(problem::DecisionProblem, [α::StructureMap])

How far the map h (by default the maximum over actions) is from commuting with the structure map α at the uncertain state m:

gap = α( T (θ ↦ h(Q[:, θ])) m )  −  h( [ α( T (θ ↦ Q[a, θ]) m ) for a ] ),

"summarise the best payoff in each state" minus "the best of the summarised payoffs". Q[a, θ] has one row per action and one column per state; m is a value of the monad of α over states (column indices by default).

  • For the expectation and h = maximum the gap is E max − max E, the expected value of perfect information, and it is nonnegative because the maximum is convex: a convex map is an oplax morphism of expectation algebras (Jensen's inequality). A concave h (minimum) gives a nonpositive gap, an affine one (sum) gives zero.
  • The same statement at a coarser m gives the other values of information: with m the distribution of the signal of an experiment and Q the posterior payoff it is EVSI; with m the distribution over the cells of a partition it is EVPPI (posterior_payoff).
  • For the worst case (InfimumAlgebra) the gap is min_θ max_a Q − max_a min_θ Q, the minimax gap, also nonnegative; for the best case (SupremumAlgebra) it is zero, since two maxima commute.

This is the precise form of "the value of information is an interchange gap" (theorem C4b of the Lean development; after Fritz and Perrone, who identify the lax and oplax algebra morphisms with the concave and convex maps).

The method for a problem uses its belief as m, its feasible actions as the rows of Q, and by default the algebra of the belief's monad (default_algebra).

julia> p = DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]);

julia> interchange_gap(p) == evpi(p)
true

CategoricalDecisionAnalysis.reward_kernel — Method
reward_kernel(f::KleisliMap{RewardMonad}; dom=:X, codom=:Y) -> RewardKernel

The RewardKernel (K, W) of CategoricalInfluenceDiagrams determined by a Kleisli map of the RewardMonad whose points are labels (Symbols): K(y | x) = Σ_r f(x)(r, y) and W[y, x] = Σ_r r · f(x)(r, y). dom and codom name the two axes. The assignment preserves composition: reward_kernel(kleisli_compose(f, g)) is compose(reward_kernel(f), reward_kernel(g)), and value pullback along f with the TotalRewardAlgebra equals value pullback along its reward kernel. A reward kernel holds Float64 tables, so this conversion leaves exact arithmetic.

CategoricalDecisionAnalysis.value_pullback — Function
value_pullback(f::KleisliMap, u, [α::StructureMap]) -> Vector
value_pullback(K::AbstractMatrix, u::AbstractVector) -> Vector
value_pullback(k::FiniteKernel, u::AbstractVector) -> Vector
value_pullback(r::RewardKernel, u::AbstractVector) -> Vector

Pull the effect (utility) u on the codomain of a kernel back to its domain:

(f* u)(x) = α( T u (f x) ),

the summary, by the structure map α, of the uncertain utility reached from x. For the distribution monad and the expectation it is the conditional expected utility E[u | x], the weakest pre-expectation of u. u is a vector aligned with f.codom, or a function; the result is aligned with f.dom. α defaults to default_algebra of the map's monad and must be a structure map of that monad (MonadMismatchError otherwise; see restrict_algebra and change_monad).

Functoriality. When α is an Eilenberg-Moore algebra (is_algebra), pullback is contravariantly functorial:

value_pullback(kleisli_identity(M, X), u, α) == u
value_pullback(kleisli_compose(f, g), u, α) == value_pullback(f, value_pullback(g, u, α), α)

which is what lets a submodel be replaced without touching the rest of an evaluation (theorem C2 of the Lean development). For a structure map that is not an algebra (CVaRMap, say) the second identity fails, and the test suite shows it.

The matrix and FiniteKernel methods are the fast path for stochastic kernels and the expectation, Kᵀ u with K[y, x] = P(y | x). For a RewardKernel (K, W) of CategoricalInfluenceDiagrams the pullback is Σ_y W[y, x] + Σ_y K[y, x] u(y), the expected reward on the way plus the expected continuation, which is that package's continuation_value(r; continuation = u).

julia> K = [9//10 1//5; 1//10 4//5];   # K[y, x] = P(y | x)

julia> value_pullback(K, [100, 20]) == [92, 36]
true

julia> f = kleisli_map(K);

julia> value_pullback(f, [100, 20]) == value_pullback(K, [100, 20])
true

CategoricalDecisionAnalysis.BayesianInverse — Type
BayesianInverse

What bayesian_inverse returns: the inversion of a channel against a prior, with zero-probability evidence as a value. Fields:

  • prior: the prior p(θ).
  • channel: the channel L[z, θ] = P(z | θ), column-stochastic.
  • joint: the sub-stochastic kernel joint[z, θ] = L[z, θ] p(θ).
  • evidence: the mass of each signal, evidence[z] = Σ_θ joint[z, θ]: the pushed prior on the signals.
  • inverse: inverse[θ, z] = P(θ | z). The column of a signal of positive mass is its posterior and sums to one; the column of a signal of mass zero is zero. It is a sub-stochastic kernel Z ⇸ Θ, total exactly on the support of the evidence.
  • states, signals: labels, when the inputs carried them (nothing otherwise).

CategoricalDecisionAnalysis.bayesian_inverse — Method
bayesian_inverse(prior::AbstractVector, channel::AbstractMatrix) -> BayesianInverse
bayesian_inverse(prior::FiniteBelief, experiment::Experiment) -> BayesianInverse
bayesian_inverse(prior::FiniteKernel, channel::FiniteKernel) -> BayesianInverse

Bayesian inversion of the channel L[z, θ] = P(z | θ) against the prior p(θ), computed as a sub-stochastic kernel followed by normalisation: first the joint L[z, θ] p(θ), then each signal's row divided by its mass, when that mass is not zero. A signal of probability zero gets the zero column in inverse and mass zero in evidence; nothing is thrown and nothing is invented (normalize_mass). Exact for rational inputs.

It agrees with DecisionAnalysis's bayes_invert: the same joint and marginal, the same posteriors where they exist, and a zero column exactly where bayes_invert returns nothing. inverse_compose composes inversions and posterior reads one off.

julia> inv = bayesian_inverse([3 // 5, 2 // 5], [4//5 1//5; 1//5 4//5; 0 0]);

julia> inv.evidence == [14 // 25, 11 // 25, 0]
true

julia> inv.inverse == [6//7 3//11 0; 1//7 8//11 0]   # the third column is zero
true

CategoricalDecisionAnalysis.inverse_compose — Method
inverse_compose(first::BayesianInverse, second::BayesianInverse) -> Matrix

The composite of two inversions, for channels in series f : Θ → Y then g : Y → Z: with first = bayesian_inverse(p, f) and second = bayesian_inverse(f p, g) (the second taken against the evidence of the first), the matrix first.inverse * second.inverse, a sub-stochastic kernel Z ⇸ Θ.

Inversion of a composite is the composite of the inversions:

bayesian_inverse(p, g * f).inverse == inverse_compose(first, second)

for every signal, with no side condition: on a signal of probability zero both sides are the zero column, and on the others both are the posterior (theorem C3 of the Lean development; the textbook statement holds "on the support", which is here the set of nonzero columns). The second inversion must have been taken against the evidence of the first (ArgumentError otherwise).

CategoricalDecisionAnalysis.normalize_mass — Method
normalize_mass(v::AbstractVector) -> (mass, normalized)

Normalisation of a sub-probability vector as a total operation: its mass Σ v and v / mass, or the zero vector when the mass is zero. A zero vector is the failure value of the sub-distribution monad: "this was observed with probability zero", kept as a value so that conditioning never throws and never invents a distribution. Entries must be nonnegative (ArgumentError).

julia> normalize_mass([1 // 10, 3 // 10])
(2//5, Rational{Int64}[1//4, 3//4])

julia> normalize_mass([0 // 1, 0 // 1])
(0//1, Rational{Int64}[0, 0])
