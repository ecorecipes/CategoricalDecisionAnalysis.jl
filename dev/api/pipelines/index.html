CategoricalDecisionAnalysis.DecisionPipeline — Type
DecisionPipeline

A decision analysis as a typed diagram. Wires are named finite variables (a name and its labels); boxes consume and produce wires and have one of five kinds:

kindshapemeaningtable
BeliefI → Θwhat is believed about a statea belief of DecisionAnalysis
ChannelΘ… → Zan observation process`P(z
PolicyZ… → Aa decision; open until a policy is boundoptional `P(a
ConsequenceA, Θ… → Yan outcome model`P(y
UtilityY… → ℝindividuals countedone number per joint input

Build single boxes with belief_box, channel_box, policy_box, consequence_box and utility_box, and join them by wire name with decision_pipeline, or categorically with compose (in series, the interfaces must match) and otimes (side by side). A wire read by several boxes is copied and a wire read by none is discarded, as in any string diagram of a Markov category. Wires that no box produces are the inputs of the pipeline (dom); the wires it exposes are its outputs (codom). An action can be an input wire: the model is then open in the action, and intervene substitutes a value on the wire.

Interpreters, each a function from the diagram into DecisionAnalysis:

  • evaluate: the kernel and expected utility of the diagram for fixed policies, compositionally (ValuedKernel);
  • decision_problem and observation_experiment: the payoff table, belief and experiment of a pipeline with one decision, on which decide, regret_table, evpi, evsi and value_with_information are then forwarded;
  • value_of_information: the values of the pipeline's own observation and of perfect information;
  • box_provenance: which boxes a number depends on;
  • fidelity_bound: the decision-loss bound read off the boxes' stated errors;
  • policy_program and strategy_program: the diagram compiled to a JuMP model.

The shape is an ACSet (PipelineGraph, from pipeline_graph); the tables are kept beside it. A pipeline is immutable: every operation returns a new one.

CategoricalDecisionAnalysis.PipelineGraph — Type
PipelineGraph

The ACSet type that holds the shape of a DecisionPipeline: parts Wire (attributes wire_name, wire_labels), Box (box_name, box_kind), InPort (in_box, in_wire) and OutPort (out_box, out_wire). The input ports of a box are ordered by part number. Tables are not stored here.

CategoricalDecisionAnalysis.ValuedKernel — Type
ValuedKernel(kernel::FiniteKernel, reward::AbstractArray)

A morphism of the expectation-semiring kernel category with entries of any real type: what a DecisionPipeline with bound policies means. kernel is the FiniteKernel K from the pipeline's inputs to its outputs, and reward is a table W of the same shape, W[y..., x...] being the expectation, given the input x, of the utility collected inside the pipeline times the indicator that the output is y. Summed over the outputs it is the expected utility given x.

It is the RewardKernel of CategoricalInfluenceDiagrams without the restriction to Float64, so a pipeline with rational tables is evaluated exactly; reward_kernel converts. compose and otimes are those of that package, (K₁K₂, W₁K₂ + K₁W₂) and (K₁ ⊗ K₂, W₁ ⊗ K₂ + K₁ ⊗ W₂), computed with compose_kernel and tensor_kernel of FiniteKernels.

AlgebraicInterfaces.compose — Method
compose(p::DecisionPipeline, q::DecisionPipeline, rs...) -> DecisionPipeline
compose(a::ValuedKernel, b::ValuedKernel, cs...) -> ValuedKernel

Sequential composition in diagrammatic order (first p, then q), a method of Catlab's compose. For pipelines, the outputs of p must be the inputs of q, the same wires in the same order (WireMismatchError); they are joined, and apart from them the two pipelines must share no wire or box name (PipelineStructureError; see rename_wires). For valued kernels it is the expectation-semiring composition (K₁K₂, W₁K₂ + K₁W₂).

Evaluation is compositional: evaluate(compose(p, q)) == compose(evaluate(p), evaluate(q)) for pipelines whose policies are bound.

CategoricalDecisionAnalysis.belief_box — Method
belief_box(name, wire, belief; error=0) -> DecisionPipeline

A Belief box I → Θ: what is believed about the state carried by wire (:name => labels). belief is a probability vector over the labels, a state label (a point belief), or any belief of DecisionAnalysis over those labels (FiniteBelief, PointBelief, CredalSet, ScenarioSet). The monad of the belief is part of the type of the pipeline: an interpreter that needs a single distribution refuses a credal or scenario belief (MonadMismatchError), and rules are matched to it as in DecisionAnalysis. error is a stated total-variation error of the belief (see fidelity_bound).

CategoricalDecisionAnalysis.bind_policy — Method
bind_policy(p::DecisionPipeline, bindings::Pair...) -> DecisionPipeline

Give policies to policy boxes (:box => policy). A policy may be

  • a table P(a | observations) with the action axis first (a stochastic policy);
  • an action label (the same action whatever is observed);
  • an array of action labels, one per joint observation;
  • a dictionary from observation labels (a label, or a tuple of labels) to action labels;
  • a function of the observation labels returning an action label.

:box => nothing opens the box again.

CategoricalDecisionAnalysis.box_provenance — Function
box_provenance(p::DecisionPipeline, [target]) -> Vector{NamedTuple}

The provenance interpreter: the boxes that a number depends on. target is a box name or a wire name, and the result lists that box (or the box producing that wire) and every box upstream of it, in an order in which each box comes after the ones it reads, each as (name, kind, inputs, output, bound, error). Without target the targets are the utility boxes, so the result is everything the expected utility depends on: the boxes whose errors enter fidelity_bound.

CategoricalDecisionAnalysis.channel_box — Method
channel_box(name, inputs, output, table; error=0) -> DecisionPipeline

A Channel box: an observation process from the inputs (one wire or a tuple of wires) to the output wire. table[z, inputs...] = P(z | inputs), output axis first; for one input it is the likelihood matrix of an Experiment (rows = signals, columns = states). error is the stated error of the table as a model of the true process: the largest total-variation distance, over the inputs, between the two (kernel_distance, fidelity_bound).

source
CategoricalDecisionAnalysis.consequence_box — Method
consequence_box(name, inputs, output, table; error=0) -> DecisionPipeline

A Consequence box: an outcome model from the inputs (typically an action and a state; one wire or a tuple of wires) to the output wire, with table[y, inputs...] = P(y | inputs), output axis first. It differs from a channel_box only in what it is for: a channel is observed before deciding, a consequence follows from the decision. error is as for a channel.

CategoricalDecisionAnalysis.decision_pipeline — Method
decision_pipeline(parts::DecisionPipeline...; inputs=nothing, outputs=Symbol[]) -> DecisionPipeline

Join pipelines (usually single boxes) by wire name: a wire that one part produces and others read is connected to all of them. The wires that no part produces are the inputs of the result (inputs may give their order), and outputs lists the wires to expose, none by default. Two wires with the same name must have the same labels (WireMismatchError); a wire produced twice, a cycle or a repeated box name throw PipelineStructureError.

julia> state = :pond => [:clear, :infected]; action = :action => [:wait, :treat];

julia> p = decision_pipeline(belief_box(:prior, state, [7 // 10, 3 // 10]),
                             policy_box(:manager, (), action),
                             utility_box(:frogs, (action, state), [90 20; 70 60]));

julia> decision_problem(p).payoff.Q
2×2 Matrix{Int64}:
 90  20
 70  60

julia> decide(p, MaxExpectedUtility()).chosen
1-element Vector{Symbol}:
 :wait

CategoricalDecisionAnalysis.decision_problem — Method
decision_problem(p::DecisionPipeline; action=nothing, baseline=nothing, feasible=nothing)
    -> DecisionProblem

The pipeline read as a payoff table and a belief: the interpreter into DecisionAnalysis for a pipeline with one decision. The decision is the one open policy box, or, when there is none, the action given as the only input wire of an open model. The states are the wires of the belief boxes (their joint, labelled a_b, when there are several, with the product belief), and

Q[a, θ] = E[ Σ utilities | do(action = a), state = θ ],

computed by cutting the policy and belief boxes and summing over every other wire. What the policy box observes plays no part here: it is read by observation_experiment. The belief is the belief box's own, whatever its form, so a credal or scenario belief gives a problem for the robust rules. baseline names the no-intervention action and feasible filters the actions, as in DecisionProblem.

CategoricalDecisionAnalysis.intervene — Method
intervene(p::DecisionPipeline, settings::Pair...) -> DecisionPipeline

Intervention as substitution on a wire (:wire => value). The value is a label (the wire is set to it), a probability vector over the wire's labels, or a belief of DecisionAnalysis. If the wire is an input of the pipeline, the value is plugged into it and the wire is no longer an input. If a box produces the wire, that box is cut out and replaced by the value: the do operation of a causal model, which removes the mechanism and keeps everything downstream. The new box is a Belief box named do_<wire>.

Setting the action wire of an open model to each of its labels in turn gives the rows of the payoff table, which is how decision_problem reads a pipeline whose action is an input wire.

source
CategoricalDecisionAnalysis.observation_experiment — Method
observation_experiment(p::DecisionPipeline; action=nothing) -> Experiment

What the decision of a one-decision pipeline observes, as an experiment on the states: L[z, θ] = P(observations = z | state = θ), with the states those of decision_problem and the signals the joint values of the wires that the open policy box reads. A policy box that reads nothing gives the experiment with one uninformative signal.

The pair (decision_problem(p), observation_experiment(p)) is the normal form of the pipeline, and it is a faithful summary only when the observation matters to the payoff through the states alone. The function checks this (the expected utility given action, state and observation must not depend on the observation) and throws PipelineStructureError otherwise: the hidden wire that the observation informs about should then be a belief box.

CategoricalDecisionAnalysis.open_influence_diagram — Method
open_influence_diagram(p::DecisionPipeline) -> NamedTuple

The pipeline as an open influence diagram of CategoricalInfluenceDiagrams: (diagram, kernels, utilities, strategy), where diagram is an OpenInfluenceDiagram with one variable per wire, a mechanism per belief, channel and consequence box, a decision per policy box (its information set the wires it reads) and a utility per utility box; kernels and utilities are the dictionaries of tables that interpret and contextual_optimize take (Float64); and strategy holds the deterministic policies of the bound policy boxes.

The pipeline's inputs and outputs are the diagram's interfaces; an input wire that a policy box reads is declared observed. A belief that is not a single distribution throws MonadMismatchError, and a bound policy that is not deterministic throws ArgumentError. The test suite uses this conversion to hold evaluate to interpret and the optimum of a pipeline to contextual_optimize.

CategoricalDecisionAnalysis.utility_box — Method
utility_box(name, inputs, table) -> DecisionPipeline

A Utility box: an effect on the inputs (one wire or a tuple of wires), a count of individuals for every joint value of them, table[inputs...]. Several utility boxes in one pipeline add. Utilities are counts of individuals of the focal species (for a disease, uninfected individuals count for and infected against), never money.

CategoricalDecisionAnalysis.value_of_information — Method
value_of_information(p::DecisionPipeline) -> NamedTuple

The value-of-information interpreter of a one-decision pipeline with a single prior: (act_now, informed, evsi, perfect, evpi), where act_now is the best expected utility with no observation, informed the value of deciding on what the policy box observes, evsi = informed − act_now, perfect the value with the state known and evpi = perfect − act_now. All are DecisionAnalysis's quantities on decision_problem and observation_experiment, so 0 ≤ evsi ≤ evpi. informed is the optimum of the pipeline over its policies, the number that contextual_optimize of CategoricalInfluenceDiagrams and the compiled programme (policy_program) return.

Catlab.Programs.GenerateJuliaPrograms.evaluate — Method
evaluate(p::DecisionPipeline; policies=nothing) -> ValuedKernel

The meaning of a pipeline for fixed policies: the ValuedKernel (K, W) from its inputs to its outputs, with K(y | x) the probability of the outputs given the inputs and W[y, x] the expected utility collected, both obtained by summing over every joint value of the wires (exact for rational tables). policies binds open policy boxes for this evaluation (:box => policy pairs or a dictionary; see bind_policy); an open box that is left unbound throws UnboundBoxError, and a belief that is not a single distribution throws MonadMismatchError.

This is a method of the evaluate of MarkovCategories and Catlab, and it is the same kind of map: a structure-preserving interpretation of a diagram. Evaluation is compositional,

evaluate(compose(p, q)) == compose(evaluate(p), evaluate(q))
evaluate(otimes(p, q))  == otimes(evaluate(p), evaluate(q))
evaluate(identity_pipeline(X)) == the identity on X with zero reward,

so a submodel can be replaced without re-deriving the rest, and it agrees with interpret of CategoricalInfluenceDiagrams on the same diagram (open_influence_diagram). Optimisation is not compositional in this sense: the best policy of a part depends on what the rest of the diagram does with its outputs, and the package offers no operation that optimises parts separately and composes the results.

Catlab.Theories.otimes — Method
otimes(p::DecisionPipeline, q::DecisionPipeline, rs...) -> DecisionPipeline
otimes(a::ValuedKernel, b::ValuedKernel, cs...) -> ValuedKernel

Parallel composition, a method of Catlab's otimes: the two pipelines side by side, with no wire or box name in common. For valued kernels it is (K₁ ⊗ K₂, W₁ ⊗ K₂ + K₁ ⊗ W₂). Evaluation preserves it: evaluate(otimes(p, q)) == otimes(evaluate(p), evaluate(q)).

CategoricalDecisionAnalysis.observation_can_matter — Method
observation_can_matter(p::DecisionPipeline, wire; box=nothing) -> Bool

A structural test, from the shape of the diagram alone: whether letting the open policy box of a one-decision pipeline observe wire can change the best expected utility, for some choice of the tables. It is false when the wire is downstream of the decision (it is not available when deciding), when the policy already reads it, or when the wire is d-separated from every utility downstream of the decision given what the policy already reads and its action (van Merwijk, Carey and Everitt 2022, single-decision case; Lauritzen and Nilsson's requisite information).

false is a guarantee: whatever the tables, observing the wire is worth exactly nothing, and no value of information needs computing (a structural zero, as opposed to a numerical one). true is a possibility, not a promise: particular tables can still make the value zero. The test suite checks the guarantee on random tables by computing the value with with_observation. box names the policy box when the pipeline has several open ones.

CategoricalDecisionAnalysis.with_observation — Method
with_observation(p::DecisionPipeline, box, wires...) -> DecisionPipeline

The same pipeline with the policy box box reading the given wires as well: the decision is then made knowing them. A bound policy is opened again, since its table no longer has the right shape. A wire that is downstream of the decision would make a cycle and throws PipelineStructureError. Comparing the optimum with and without the extra wire (solve_policy_program) is the value of observing it.
