Selection functions and sequential problems

CategoricalDecisionAnalysis.ChanceStage — Type
ChanceStage(name, outcomes, law)

A stage of a SequentialProblem at which nature moves. law is a value of the problem's monad over outcomes (a FiniteDistribution for a probabilistic problem, a FiniteSubset when only the possible outcomes are known, a CredalHull for a set of candidate distributions), or a function of the history (the tuple of earlier moves) returning one, when what can happen depends on what was done or seen before.

source
CategoricalDecisionAnalysis.DecisionStage — Type
DecisionStage(name, actions)

A stage of a SequentialProblem at which the decision-maker chooses one of actions, knowing every earlier move.

source
CategoricalDecisionAnalysis.RuleSelection — Type
RuleSelection

A decision rule of DecisionAnalysis exhibited as a selection function on the actions of a problem, with outcome type ℝ^Θ (an action's payoff in every state): (A → ℝ^Θ) → P(A). Built by rule_selection. It has two parts that can be changed independently, and changing them is how one rule becomes another:

  • the algebra box: transform (:identity, :regret or :relative_regret, applied to the payoff table first) and algebra (a StructureMap) that summarises each action's row against the belief, read in the monad of the algebra (belief_value); with uniform set, the belief is replaced by the uniform distribution on the states it allows, which is how the Laplace rule is an expectation;
  • the selection box: selector, which is :optimize (every best action; ties are all returned), a threshold (:threshold, level) (every action that is good enough), or one of the set-valued rules over a credal set, :e_admissible, :maximal and :interval_dominance.

select gives the chosen actions, rule_scores the score of every feasible action and quantifier the best score. The scores and choices equal those of DecisionAnalysis's decide for the same rule, which the test suite checks for every rule on random problems; the two computations share no code beyond the linear-programme solver used for E-admissibility.

source
CategoricalDecisionAnalysis.SelectionFunction — Type
SelectionFunction(name, points, monad, algebra, choose)

A selection function ε : (X → ℝ) → T X on the finite set points, for the uncertainty monad monad (T) and the structure map algebra (α : T ℝ → ℝ). choose takes a function q : X → ℝ (an effect: what each point is worth) and returns a value of T X (which point, or points, or distribution over points, is selected). select applies it and quantifier gives the worth of what is selected, α(T q (ε q)).

With the identity monad it is the classical selection function of Escardó and Oliva, such as "a point where q is largest" (argmax_selection); its quantifier is then the maximum. With the distribution monad a chance node is the selection function that ignores q and returns its law (constant_selection); its quantifier is the expectation. That one type covers both is what lets selection_product express a decision followed by a chance node.

source
CategoricalDecisionAnalysis.SequentialProblem — Type
SequentialProblem(monad, stages, payoff)
SequentialProblem(stages, payoff)

A finite sequential decision problem in stage form: a list of DecisionStages and ChanceStages, played in order with every earlier move known at every stage (perfect recall, full observation), and a payoff function of the complete history (a tuple of one move per stage) counted in individuals. monad is the uncertainty monad of the chance stages and defaults to the DistributionMonad.

A decision made on a noisy observation of a hidden state is written with the observation first: a chance stage for the signal with its marginal law, the decision, and then a chance stage for the state whose law is the posterior given the signal (bayesian_inverse); that flip is the textbook decision tree.

Solve it with backward_induction (stage by stage, for criteria that admit it) or policy_search (every policy, any criterion).

source
CategoricalDecisionAnalysis.SequentialSolution — Type
SequentialSolution

What backward_induction and policy_search return. Fields:

  • criterion: the name of the criterion.
  • value: the value of the returned policy under the criterion, computed from the law of its plays (for minimax regret, its largest regret: lower is better).
  • policy: a dictionary from histories at decision stages (tuples of earlier moves) to the action chosen there.
  • law: the uncertain play under the policy, a value of the problem's monad over complete histories.
  • method: :backward_induction or :policy_search.
  • label: what the solution is. :optimal: the policy is best for the criterion applied to the whole problem. :nested: the criterion is monotone but not an algebra (CVaR, say) and the stage-by-stage answer was asked for; the policy is best for the nested rule, the criterion applied stage by stage, which is a different rule, and recursion_value is its nested value while value is what the policy is worth under the criterion applied to the whole problem. :heuristic: minimax regret solved stage by stage; no optimality is claimed.
  • recursion_value: the value computed by the stage-by-stage recursion; equal to value when the label is :optimal, and nothing for minimax regret.
  • policies: the number of policies examined (policy_search) or nothing.

CategoricalDecisionAnalysis.argmax_selection — Method
argmax_selection(points; monad=IdentityMonad(), algebra=default_algebra(monad), ties=:first)

The selection function "a point of points where the effect is largest". With ties = :first (the default) it returns the first maximiser in the order of points, as a certain value of monad (monad_unit): nothing is random, as in DecisionAnalysis. With ties = :all, for the PowersetMonad only, it returns every maximiser as a FiniteSubset (the set-valued variant; the algebra defaults to SupremumAlgebra). Its quantifier is the maximum.

source
CategoricalDecisionAnalysis.argmin_selection — Method
argmin_selection(points; monad=IdentityMonad(), algebra=default_algebra(monad), ties=:first)

The selection function "a point where the effect is smallest", as argmax_selection; used on losses such as regret.

CategoricalDecisionAnalysis.backward_induction — Method
backward_induction(problem::SequentialProblem, criterion; nested=false, heuristic=false)
    -> SequentialSolution

Solve a sequential problem stage by stage from the last, as the iterated selection_product of one selection function per stage (the first best action at a decision stage, the stage's law at a chance stage). What the result means depends on the class of the criterion (backward_induction_class):

  • :flat (expectation, worst case, best case, lower and upper expectation, certainty equivalents): the structure map is an Eilenberg-Moore algebra and monotone, so the stage-by-stage value is the criterion applied to the whole problem and the policy is a best one, equal in value to policy_search (Lean TwoStage.IsBackwardPolicy.flatValue_optimal; tested against exhaustive search). The solution is labelled :optimal.
  • :nested (CVaR, quantiles, Hurwicz, Laplace, α-maxmin): the structure map is monotone but not an algebra. Backward induction is then optimal for the nested rule, the criterion applied at every stage to the values of the next, and that is a different rule from the criterion applied to the distribution of the final payoff (Lean cvar_two_step_ne_one_step): the policy it finds can be strictly worse for the latter (cvar_backward_induction_suboptimal). The function throws BackwardInductionError unless nested = true, and then labels the solution :nested: recursion_value is the nested value, which no policy exceeds, and value is what the policy is worth under the criterion applied to the whole problem.
  • :none (minimax regret): regret is measured against a menu, and the menu of a subproblem is not the menu of the problem (minimaxRegret_backward_induction_suboptimal). The function throws unless heuristic = true, which runs the recursion with regret measured within each subproblem and labels the solution :heuristic; nothing is claimed for it.

heuristic = true also accepts a :nested criterion. A chance stage's law is a FiniteDistribution, which is normalised by construction; the theorem needs that (a sub-stochastic stage, with a stopping probability, breaks it), so there is no way to pass one. For a credal problem (CredalMonad) the optimum is with respect to the sequential composite of the credal kernels, which lets nature choose afresh at every chance stage.

source
CategoricalDecisionAnalysis.backward_induction_class — Method
backward_induction_class(criterion) -> Symbol

What solving stage by stage means for a criterion (a StructureMap, an aggregator or rule of DecisionAnalysis, or a RuleSelection):

  • :flat: the structure map is an Eilenberg-Moore algebra and monotone, so the stage-by-stage (nested) value is the criterion applied to the whole problem, and backward induction is optimal for it. Expectation, worst case, best case, lower and upper expectation, certainty equivalents.
  • :nested: monotone but not an algebra. Backward induction is optimal for the nested rule, which is a different rule. CVaR, quantiles, Hurwicz, Laplace, α-maxmin.
  • :none: no stage-by-stage form is offered: minimax regret (and any rule with a regret transform or a threshold selector), and a structure map that is not monotone.

admits_backward_induction is true exactly for :flat. The classification is that of the Lean development (Finite/Sequential.lean, Finite/BackwardInductionFails.lean): monotonicity alone makes backward induction optimal for the nested value, and the algebra laws are what make the nested value the flat one.

CategoricalDecisionAnalysis.constant_selection — Method
constant_selection(points, value; monad, algebra=default_algebra(monad))

The selection function that ignores the effect and returns value, a value of monad over points: a chance node. Nature does not choose by looking at the payoffs. Its quantifier is the structure map applied to the effect: the expectation for a distribution, the worst case for a set under the InfimumAlgebra. monad defaults to the one value is a value of.

source
CategoricalDecisionAnalysis.nested_value — Method
nested_value(problem::SequentialProblem, policy::AbstractDict, criterion)

The nested value of a policy under a scalar criterion: the structure map applied at every chance stage to the values of the next stage, from the last stage backwards. For a criterion of class :flat it equals policy_value; for a :nested one (CVaR, say) it is the value of a different rule, the one that backward_induction with nested = true optimises.

source
CategoricalDecisionAnalysis.optimal_plays — Method
optimal_plays(problem::SequentialProblem) -> FiniteSubset

Every complete history of a deterministic sequential problem (decision stages only) that attains the largest payoff, computed by the product of set-valued selection functions (argmax_selection(...; ties = :all) in the PowersetMonad). For such problems the product returns exactly the set of optimal plays, which the test suite checks against enumeration.

It is not offered for problems with chance stages. With nature's moves in the product, the set it returns is the plays of the policies that are optimal in every subproblem, which is in general a strict subset of the plays of all optimal policies (a worst-case-optimal policy may do anything off the worst path), and for games with several players set-valued products are known to be wrong (Bolt, Hedges and Zahn). A problem with a chance stage throws ArgumentError.

source
CategoricalDecisionAnalysis.pareto_selection — Method
pareto_selection(problems::AbstractVector{<:DecisionProblem}; algebra=ExpectationAlgebra(), atol=0, rtol)
    -> Vector{Symbol}

The Pareto front as a set-valued selection function with outcome type ℝ^k, one coordinate per objective: the feasible actions whose vector of scores (one per problem, each summarised by algebra) is not dominated by another action's (at least as good in every objective and better in one). It reproduces DecisionAnalysis's decide(problems, ParetoFront()). The problems must have the same feasible actions.

source
CategoricalDecisionAnalysis.policy_law — Method
policy_law(problem::SequentialProblem, policy::AbstractDict)

The uncertain play when policy (a dictionary from histories at decision stages to actions) is followed: a value of the problem's monad over complete histories, built by chaining the chance stages with monad_bind.

source
CategoricalDecisionAnalysis.policy_search — Method
policy_search(problem::SequentialProblem, criterion; max_policies=1_000_000)
    -> SequentialSolution

Solve a sequential problem by examining every policy: the exact optimum for any criterion, at a cost that grows very fast with the number of decision histories (more than max_policies policies throws ArgumentError). criterion is a StructureMap, a DecisionAnalysis aggregator (Expectation(), CVaR(1 // 4), ...) or scalar rule (MaxExpectedUtility(), Maximin(), MinimaxRegret(), ...).

For a scalar criterion α the value of a policy is α of the payoff of its uncertain play (policy_value) and the largest is returned, with the first policy that attains it. For minimax regret the problem's monad must be the PowersetMonad with chance outcomes that do not depend on the history; a scenario fixes one outcome per chance stage, the regret of a policy in a scenario is the best payoff achievable there with hindsight minus its own, and the policy with the smallest largest regret is returned.

This is the reference that backward_induction is tested against, and the method to use for criteria that do not admit backward induction.

source
CategoricalDecisionAnalysis.policy_value — Method
policy_value(problem::SequentialProblem, policy::AbstractDict, criterion)

The value of following policy under a scalar criterion (a StructureMap, a DecisionAnalysis aggregator, or a rule built on one): the structure map applied to the payoff of the uncertain play, α(T payoff (policy_law)).

CategoricalDecisionAnalysis.quantifier — Method
quantifier(ε::SelectionFunction, q)
quantifier(r::RuleSelection, problem::DecisionProblem)

The quantifier of a selection function at q: the worth of what it selects, α(T q (ε q)). For argmax_selection it is max q, for a chance node (constant_selection of a distribution) the expectation of q. For a RuleSelection it is the best score of the rule in the problem.

source
CategoricalDecisionAnalysis.rule_scores — Method
rule_scores(r::RuleSelection, problem::DecisionProblem) -> Vector

The score of every feasible action of problem under the rule: the structure map applied to the action's (transformed) payoffs pushed along the belief, α(T (θ ↦ M[a, θ]) m). With a regret transform the score is a loss, lower is better, and it is computed as −α(T (θ ↦ −M[a, θ]) m), the convention of DecisionAnalysis (the worst case of a regret is the largest regret). The set-valued rules over a credal set have no scalar score and return nothing.

source
CategoricalDecisionAnalysis.rule_selection — Method
rule_selection(rule) -> RuleSelection
rule_selection(; algebra, selector=:optimize, transform=:identity, name=:custom)

A rule of DecisionAnalysis as a RuleSelection: any DecisionRule (and so MaxExpectedUtility, Maximin, Maximax, MinimaxRegret, GammaMaximin, Satisfice and every rule assembled from an aggregator, a transform and a selector), and the set-valued EAdmissible, Maximal and IntervalDominance. The keyword form assembles one from its two boxes directly; algebra may be a StructureMap or a DecisionAnalysis aggregator. With a regret transform the algebra is read on the side of losses, as in DecisionAnalysis: the worst case (InfimumAlgebra) of a regret is the largest regret, so minimax regret is rule_selection(; algebra=InfimumAlgebra(), transform=:regret).

ParetoFront compares several objectives and is exhibited by pareto_selection.

julia> t = PayoffTable([:nothing, :levee, :relocate], [:low, :moderate, :high, :extreme],
                       [0 -10 -60 -150; -20 -20 -25 -90; -48 -48 -48 -48]);

julia> p = DecisionProblem(t, [1 // 2, 3 // 10, 3 // 20, 1 // 20]);

julia> select(rule_selection(MaxExpectedUtility()), p)
1-element Vector{Symbol}:
 :nothing

julia> select(rule_selection(; algebra=InfimumAlgebra()), p)     # swap the algebra box
1-element Vector{Symbol}:
 :relocate

julia> select(rule_selection(; algebra=InfimumAlgebra(), transform=:regret), p)  # worst regret
1-element Vector{Symbol}:
 :levee

CategoricalDecisionAnalysis.select — Method
select(ε::SelectionFunction, q)
select(r::RuleSelection, problem::DecisionProblem; atol=0, rtol) -> Vector{Symbol}

Apply a selection function. For a SelectionFunction, q is a function on its points or a vector aligned with them, and the result is a value of its monad over the points. For a RuleSelection the result is the set of actions the rule chooses in the problem, in table order (possibly empty for a satisficing rule), with the tie tolerance of DecisionAnalysis's decide.

CategoricalDecisionAnalysis.selection_product — Method
selection_product(ε::SelectionFunction, δ) -> SelectionFunction

The product of selection functions: ε on X and δ on Y, where δ is a selection function or a function x ↦ δ_x giving one for each point of X (the later choice may depend on the earlier one). The result is a selection function on the pairs (x, y):

(ε ⊗ δ)(q) = ε(f) >>= λx. T (y ↦ (x, y)) (b x),
b x = δ_x(y ↦ q((x, y))),      f x = α( T (y ↦ q((x, y))) (b x) ).

In words: for each first move x, let the second stage select against what is left of q; value x by what that selection is worth; let the first stage select against those values; and return the joint play. Both factors must have the same monad and structure map (MonadMismatchError).

With the identity monad this is the product of Escardó and Oliva, and iterating it over the stages of a deterministic problem computes an optimal play by backward induction (theorem C7a). With chance nodes it is the monadic product (Hedges); it then computes a best policy when the structure map is an Eilenberg-Moore algebra and monotone (admits_backward_induction, theorem C7b) and not in general otherwise. backward_induction builds the iterated product for a SequentialProblem and enforces that condition.

julia> first_move = argmax_selection([:a, :b]);

julia> second_move = argmax_selection([:c, :d]);

julia> worth = Dict((:a, :c) => 1, (:a, :d) => 4, (:b, :c) => 3, (:b, :d) => 2);

julia> select(selection_product(first_move, second_move), xy -> worth[xy])
(:a, :d)
